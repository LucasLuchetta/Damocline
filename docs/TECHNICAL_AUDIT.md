# Technical audit: integrated capacity milestones

This audit was reconciled against `master` at `c9f25a1` after PRs #112 and #113 merged. PRs #103–#113 added bounded campaign checkpoints, redacted evidence export, exact local generator calibration gates, trusted local HTTPS calibration profiles, and bounded active stabilization, alongside the previously recorded campaign, report-history and cleanup work. This branch completes per-journey weighted-profile selection and its start/actor accounting in both workload modes; broader workload representativeness remains open.

## What the recent merges delivered

PRs #76 through #96 extended the bounded G0 acceptance lab, calibrated 30 exact request-shape/rate/connection-policy combinations, recorded effective Linux cgroup CPU entitlement, classified DNS and connection-establishment failures, and added loopback ledgers for drain, interruption, and response-size boundaries. PR #92 added persisted campaign auditing and named step/profile drift screening; PR #93 removed a false closed-loop arrival signal; PR #94 added journey-window SLO evidence; PR #95 made audit and demand findings traceable to saved content digests; PR #96 separated successful journey throughput from request rate. These changes strengthen local fixtures and report accounting. They do not validate arbitrary application endpoints or establish sustainable capacity. `docs/G0_STATUS.md` records the fixture and platform limits.

## Cohesive delivery sequence

1. **Representative workload (remaining G1-01/G1-04/G1-07/G1-08/G1-11/G1-13/G1-14/G1-17):** add per-workflow identity context and a bounded partly-open session model only with explicit arrival/session semantics; validate sanitized aggregate mix provenance and freshness; broaden adversarial template and state-lifecycle fixtures. Reuse the existing profiles, actor-local cookie jars, extraction, synthetic IDs, and cleanup suffix.
2. **Sustained campaign decisions (remaining G2-02/G2-04/G2-07/G2-10/G2-11):** preserve bounded admission-stop/drain evidence and censored-work accounting, add application-specific bounded data reset and independent authenticated session workflows to complement the new cooldown/trial IDs, and exercise leak/latency creep across longer controlled loopback runs. Reuse the current campaign phase engine and offline schedule reader.
3. **Evidence-grade demand answer (G2-14/G2-15/G2-18/G3-01 through G3-12):** trial-level and dependence-aware uncertainty, declare workload objectives before execution, report highest validated and first failing tested levels separately, and retain traceable evidence without inferring untested limits.
4. **Optional diagnosis (G4-01 through G4-04/G4-09/G4-12):** read-only time-aligned adapter contract and bounded Docker/PostgreSQL fixtures, while preserving the HTTP-only unknown-cause path.

Each block should include implementation, local success/failure/cancellation fixtures, reader compatibility where output changes, documentation, and a reproducible validation record. No single block certifies human-user capacity.
