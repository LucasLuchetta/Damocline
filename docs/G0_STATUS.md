# G0 acceptance matrix

Capacity audit evidence IDs are SHA-256 hashes over canonical JSON marshaled from decoded campaign/report structs. Assessments separately record the SHA-256 of the exact bounded source campaign bytes and exact auditor executable; generated replay can require all three values. The campaign-byte hash covers whitespace and fields unknown to this reader, while the executable hash identifies the implementation used. These digests are unkeyed: they do not authenticate producer identity, build origin, or source custody, and do not make local reports immutable. Multi-level collections now require matching recorded runner identity and effective CPU entitlement across all required phases and levels; this verifies metadata consistency only, not physical host identity.

This matrix records implementation, automated-test and runtime-validation evidence. `VALID_WITHIN_ENVELOPE` is reachable only for the calibrator-owned 30-second loopback soak; ordinary target runs remain limited. No item implies general application-capacity certification.

## G0 exit decision

G0 remains **open**. Positive results are established only for the controlled Windows and recorded Docker Desktop/WSL2 loopback soaks. Cross-host/hardware-class equivalence, bare-metal Linux, broad transport/failure matrices, statistical dependence handling, and multiple other G0 acceptance gaps remain.
