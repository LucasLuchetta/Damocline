# G0 acceptance matrix

Capacity audit evidence IDs are SHA-256 hashes over canonical JSON marshaled from decoded campaign/report structs. Assessments separately record the SHA-256 of the exact bounded source campaign bytes and exact auditor executable; generated replay can require all three values. The campaign-byte hash covers whitespace and fields unknown to this reader, while the executable hash identifies the implementation used. These digests are unkeyed: they do not authenticate producer identity, build origin, or source custody, and do not make local reports immutable. Multi-level collections now require matching recorded runner identity and effective CPU entitlement across all required phases and levels; this verifies metadata consistency only, not physical host identity.

This matrix records implementation, automated-test and runtime-validation evidence. `VALID_WITHIN_ENVELOPE` is reachable only for the calibrator-owned 30-second loopback soak; ordinary target runs remain limited. No item implies general application-capacity certification.

## G0 exit decision

G0 is **closed** on the roadmap exit test, within the local reference scope ([ADR 0149](adr/0149-close-g0-on-the-exit-test.md)). Passing G0 is not a sustainable application capacity result.

- **Repeatable calibration on the actual generator class:** at merged revision `418b167`, cross-built linux/amd64 acceptance and calibrator binaries were checked by SHA-256 across the upload to an independent bare-metal Linux x86-64 host with 4 CPUs. Two bounded repeats then passed as `PASS_LOCAL_REFERENCE_ONLY`, with every manifest rule passing.
  - Effective CPU capacity was detected (`runtime_logical_cpus_and_gomaxprocs`, ADR 0144).
  - All 11 controlled soaks were `VALID_WITHIN_ENVELOPE`.
  - Hosted Windows and Linux acceptance also passed in CI.
- **Workload inside the validated envelope:** opt-in exact calibration gates stop before any traffic when evidence is stale, mismatched or not equivalent. Safety ceilings are unchanged (G0-11).
- **Scheduling, cancellation, timing and counts reconcile:** loopback fixtures check these against independent server ledgers. This includes bounded in-process CPU pressure, where over-tolerance runs are classified as degraded, not valid (ADR 0145). It also covers connection caps, abort and kill stages, mixed journeys, and DNS and TLS failure subtypes (ADR 0147).
- **Process health present or explicitly unavailable:** generator CPU, sampler gaps and RSS are recorded, or marked unavailable.

The "remaining" column of each gate above is carried forward as post-G0 hardening and must not be described as verified. ADR 0148 also defers four items past G0:

- record signing
- physical host attestation
- validated calibration lifetime
- default gate enforcement

## CPU source availability correction (schema v33)

Stationary Go CPU-class counters are now unavailable rather than a measured
idle window. OS process CPU and existing sampler/headroom gates remain required;
legacy report requirements remain versioned. Deterministic source-availability
and reader/export fixtures accompany a bounded four-second native-engine CPU
pressure fixture (20 loopback starts, child GOMAXPROCS=1, 20-second parent
deadline). The fixture requires independent request reconciliation, measured
process CPU at least 90%, a client-only pressure signal and LIMITED quality.
This adds coverage for G0-07/G0-14, not completion: direct sampler CPU-cost
calibration, advancing snapshot freshness, controlled external host pressure,
hardware classes and bare-metal Linux remain unverified. See ADR 0132.

## Report serialization resource boundary

The shared writer now inspects plain artifact values, field metadata and
potential escaped names before encoding, including nil/omitted descendants and
embedded fields. Builtin composite zero checks are precharged for their possible
byte/node work, including hidden fields and zero-sized array elements.
Its 32 MiB accounting budget and 128-level nesting guard complement the exact
16 MiB output limit; they are not a process-RSS ceiling. Tests reject callback
execution, oversized string/map copies and excessive encoded field names.
Bounded integration fixtures perform 32 accepted 1 MiB writes and 32 rejected
64 MiB writes with byte/temp-file reconciliation, an 8 MiB retained-heap-growth
screen and a 256 MiB child peak-RSS screen. Linux additionally exercises a
kernel EFBIG partial write in an isolated child and verifies destination
preservation, temporary-file cleanup and a subsequent successful write.
This is partial G0-09 coverage. Aggregate worker memory, longer engine leaks,
actual full-disk failure, interrupted replacement and crash durability remain
unverified. See ADR 0135 for measurement boundaries and previous failed probes.

## Repeated engine memory fixture

An integration fixture runs one warm-up and three measured native-engine runs
in one fresh child, with the owned HTTP server and its independent request/byte
ledgers in the parent process. Each run uses 50 workers, 100 scheduled starts/s
for two seconds and 2 MiB responses, retaining the unchanged request-rate ceiling.
The first 50 handlers send response prefixes before a shared final-byte barrier.
All admitted work and body bytes must reconcile; explicit busy/late drops are
retained, and quality remains LIMITED. Post-GC heap growth is screened against
16 MiB above warm-up and generator-only process peak RSS against 512 MiB.
The fixture logs the actual workload, retained heap and OS measurement method.
See ADR 0138 for its command, deadlines and measurement boundaries.

This provides a bounded aggregate-worker and repeated-run regression screen,
not long-duration leak freedom, induced low-memory/OOM validation, cross-host
evidence or capacity qualification. The report-writer fixture remains separate.

## CPU observation presence in saved artifacts

Schema-v12+ valid CPU claims require explicit numeric observations before typed
decoding across direct runs, completed/pending campaign phases and exploration
probes. Historical pre-v12 missing process means remain readable with an unknown
marker preserved through re-encoding; they cannot qualify CPU headroom. Peak
pressure remains independent, and insights/redacted exports disclose unknown
means. This closes one concrete missing-versus-zero path in G0-17; other profile,
audit and campaign field contracts remain open. See ADR 0136.

## Predeclared objective presence

Both campaign families reject absent/null fields inside recorded objective
contracts from their introduction versions (closed-loop v13, open-arrival v8).
This includes valid zero error/drop controls that typed decoding otherwise
cannot distinguish from omission. Shared raw reader checks run before offline
assessment/report output; older schemas keep their original lack of a contract.
This adds G0-17 coverage, not proof of when criteria were chosen or completion of
other artifact-field and measurement requirements. See ADR 0137.
