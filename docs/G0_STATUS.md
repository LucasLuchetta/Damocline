# G0 acceptance matrix

This matrix records the state of the G0 criteria after PRs #56–#61 were merged. `Implemented` means executable code exists; `Tested` means automated tests exercise it; `Validated` is limited to the named local fixture, host and CI run. None of those words imply general application-capacity certification.

PR #57 merged schema-v13 per-step/per-profile window ledgers for G0-12/G0-16; PR #58 aligned the insights reader with v13 and added future-schema rejection; PR #59 added v1-v13 golden reader fixtures; PR #60 recomputes the saved workload digest for the report-reconstructable reference shape; PR #61 added an explicit empty-body case to the native-engine matrix. This branch introduces report schema v14 connection-policy recording and applies `reuse` versus `new_per_request` to the engine transport; the reuse-only preflight explicitly marks the latter outside reference. This does not enable a positive quality state or cover omitted request details, endpoint identity, TLS success, or broader workload ranges.

## Current platform evidence

- PR #56 CI run `39085479115` passed on Linux and Windows for source vet/race/reference/transport jobs and passed source cross-builds for Linux AMD64, Windows AMD64, macOS AMD64 and macOS ARM64. PRs #57–#61 were subsequently merged after their Linux and Windows CI passed; #59 added the v1-v13 suite and #61 added the native-engine empty-body fixture.
- This development host is Windows AMD64 with Go 1.26.3. The local basic, extended and three-repeat fixtures passed their ledgers and scheduler-lag checks on this host. Local validation does not substitute for Linux runtime validation or another hardware class.
- Full runtime repeated calibration remains validated locally only on Windows AMD64; Linux CI loopback tests do not establish broader host-class equivalence. The current connection-policy increment has local Windows test/race/build validation; Linux/Windows CI is pending.

## G0 exit decision

G0 remains **open**. In particular, no valid positive `VALID_WITHIN_ENVELOPE` example exists, cross-host and host-class equivalence are not established, and report-schema migration coverage is incomplete. A successful CI run alone cannot close these evidence gaps.
