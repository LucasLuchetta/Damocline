## Current platform evidence

- PRs #57 through #70 passed their recorded CI before merge, including native-engine trusted TLS, truncated-body reconciliation, journey ledgers, scheduler cancellation classification, and positive-soak scheduler-lag gates. PR #68's first Windows extended calibration attempt observed two late starts and 16.6 ms maximum scheduler lag against its 10 ms stage bound; a single job retry passed without changing the bound. Linux runtime calibration remains pending.
- The controlled positive soak ran on 12 logical CPUs and reconciled 300 client arrivals/completions with 300 independent child-fixture completions. Its private report is preserved under `.damocline/calibration/controlled-positive-2026-10-18-final.json` (gitignored).
- Current local Windows basic, extended and three-repeat runs reconciled the v3 workload matrix: 50/50 arrivals per profile, exact client response lengths, and matching independent server request/body byte totals; all reported `REFERENCE_SMOKE_PASSED` with zero discrepancies. The 30-second soak also produced `VALID_WITHIN_ENVELOPE` for its calibrator-owned HTTP loopback case. The separate HTTP/HTTPS transport matrix passed 10/10 fixtures. This Windows execution used 12 logical CPUs and Go 1.26.3. It does not validate another hardware class, Linux runtime behavior, TLS workload calibration, or external application capacity.

## G0 exit decision

G0 remains **open**. A positive result is established only for the controlled Windows loopback soak. Cross-host/hardware-class equivalence, broad transport/failure matrices, statistical dependence handling, and multiple other G0 acceptance gaps remain.
