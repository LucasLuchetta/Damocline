# G0 acceptance matrix

This matrix records the state of the G0 criteria after PR #56 was merged at `463d7e6`. `Implemented` means executable code exists; `Tested` means automated tests exercise it; `Validated` is limited to the named local fixture, host and CI run. None of those words imply general application-capacity certification.

The current working branch adds schema-v13 per-step/per-profile window ledgers for G0-12/G0-16. Local Windows validation on Go 1.26.3 passed `go vet ./...`, `go test -count=1 ./...`, `go test -race -count=1 ./...`, both CLI builds, and `scripts/validate-local.ps1`; the slow-minority profile fixture passed three consecutive repetitions. The script recorded passing basic (385/385), extended (1310/1310), and repeated (555/555) loopback calibrations plus 10/10 local transport fixtures, all with zero ledger discrepancies and scheduler lag within the declared fixture tolerance. These local changes remain pending review and Linux/Windows CI validation until their PR is merged.

## Current platform evidence

- PR #56 CI run `39085479115` passed on Linux and Windows for source vet/race/reference/transport jobs and passed source cross-builds for Linux AMD64, Windows AMD64, macOS AMD64 and macOS ARM64.
- This development host is Windows AMD64 with Go 1.26.3. The local basic, extended and three-repeat fixtures passed their ledgers and scheduler-lag checks on this host. Local validation does not substitute for Linux runtime validation or another hardware class.
- The schema-v13 window work is present only on the current review branch; PR #56 CI does not validate it. Full local Windows validation passed, but this increment still needs PR CI on Linux and Windows.

## G0 exit decision

G0 remains **open**. In particular, no valid positive `VALID_WITHIN_ENVELOPE` example exists, cross-host and host-class equivalence are not established, and report-schema migration coverage is incomplete. A successful CI run alone cannot close these evidence gaps.
