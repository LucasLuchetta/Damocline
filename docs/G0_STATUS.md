This matrix records implementation, automated-test and runtime-validation evidence. `VALID_WITHIN_ENVELOPE` is reachable only for the calibrator-owned 30-second loopback soak; ordinary target runs remain limited. No item implies general application-capacity certification.

## Current platform evidence

- PRs #57 through #73 are merged, including native-engine trusted TLS, truncated-body reconciliation, workload-shape calibration, transport failure ledgers, and sampler wall-time screening. The controlled positive soak remains Windows-only; Linux runtime calibration remains pending.
- The controlled positive soak ran on 12 logical CPUs and reconciled 300 client arrivals/completions with 300 independent child-fixture completions. Its private report is preserved under `.damocline/calibration/controlled-positive-2026-10-18-final.json` (gitignored).
- Windows AMD64, Go 1.26.3, 12 logical CPUs: historical schema-v4 basic, extended, and repeat runs remain as recorded below; new schema-v5 acceptance passed twice with 30 exact profile pairs per run, 980/980 aggregate independent server requests, zero ledger discrepancies, and 300/300 controlled soaks recalculated as `VALID_WITHIN_ENVELOPE`. The separate HTTP/HTTPS transport matrix passed 10/10.
- Linux AMD64 under Ubuntu 22.04 on WSL2, Go 1.26.3, 12 reported logical CPUs: schema-v5 acceptance passed twice with the same 30-profile and 980/980 aggregate ledger gates, 300/300 controlled soaks recalculated as `VALID_WITHIN_ENVELOPE`, and 10/10 transport cases. The binary ran as Linux amd64, but the kernel/runtime environment is WSL2 on the same physical Windows host; this is not independent bare-metal Linux or cross-host validation.

## G0 exit decision

G0 remains **open**. A positive result is established only for the controlled Windows loopback soak. Cross-host/hardware-class equivalence, broad transport/failure matrices, statistical dependence handling, and multiple other G0 acceptance gaps remain.
